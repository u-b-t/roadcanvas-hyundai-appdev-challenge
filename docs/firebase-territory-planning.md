# 땅따먹기 서버 설계 전제

주행 경로로 영역을 확보하고 기존 소유 영역과 겹친 부분을 빼앗는 기획이다. 아직 앱 기능이나 Firebase 컬렉션을 확정·배포하지 않았다. 현재 `artworks`와 `drawings`는 소유 영역을 나타내지 않는다.

구현 전에 정할 사항:

- 한 바퀴의 인정 조건: 시작·종료 거리, 도로로 둘러싸이지 않은 경로, 이동 중 끊김 및 최소 크기.
- 획득 단위: 도형 자체를 계산할지, 지도를 고정 격자로 나눌지. 격자는 간단한 소유권 표현이 가능하지만 경계가 근사되며 격자 크기와 지역 좌표 체계를 정해야 한다.
- 여러 차량이 같은 영역을 거의 동시에 제출했을 때 인정 순서, 탈취 규칙, 재시도 및 중복 제출 식별자.
- 내 주변 지도 범위의 영역 검색과 면적 계산, 사용자별 전체 면적 순위, 영토 변경 이력과 기록 보관 기간.
- GPS 값 부족·오류와 불합리한 위치 제출의 처리, 앱 종료·오프라인 중 기록의 제출 방식.

영역 표현, 지도 범위 조회, 동시 탈취·중복 제출·오프라인 재시도의 에뮬레이터 검증 결과와 계약 후보, 기획 결정 목록은 [땅따먹기 소유권 모델 검증](firebase-territory-ownership.md)에 있다.

Firestore 직접 접근과 클라이언트 계산만으로 시작하면 여러 영역 문서의 갱신 범위, 트랜잭션 제한, 충돌 재시도와 영역 계산 신뢰성을 검토해야 한다. Cloud Functions나 별도 서버 없이 임의의 겹치는 도형을 안전하게 일괄 갱신할 수 있다고 가정하지 않는다. 게임 규칙과 예상 범위를 정한 뒤 Firestore에서 가능한 최소 모델을 실험하고 문서 및 규칙을 만든다.
