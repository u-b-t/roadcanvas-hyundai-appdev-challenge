# 자유그림 공개와 투표 클라이언트 명세

이 문서는 Firebase 서버 계약이다. 앱의 자유그림·작품 목록·투표 화면은 별도 작업이다. Firebase 익명 인증을 사용하며, 앱 데이터 삭제나 기기 변경으로 익명 계정을 잃으면 기존 작품 소유권과 투표를 복구할 수 없다. Cloud Functions는 사용하지 않는다.

## 경로와 필드

`artworks/{artworkId}`는 공개용 별도 문서다. 클라이언트는 충돌 가능성이 낮은 UUID를 최초 한 번 생성해 재시도에도 유지한다. 개인 기록 `users/{uid}/drawings`는 그대로 비공개다. Firestore 시각은 timestamp, 거리 단위는 미터, 시간은 밀리초다.

| 필드 | 타입과 의미 |
| --- | --- |
| `ownerUid` | 인증 사용자 UID. 생성 후 변경 불가 |
| `nickname` | 표시할 작성자 닉네임. 1~30자 |
| `title` | 작품 이름. 1~20자. 클라이언트가 앞뒤 공백을 제거하고 공백뿐인 이름을 막는다 |
| `visibility` | `DRAFT` 또는 `PUBLISHED` |
| `createdAt` | 최초 생성 시각. 생성 후 변경 불가 |
| `pointChunkCount` | 경로 청크 수. 0~10,000 정수 |
| `distanceMeters`, `durationMillis` | 0 이상 숫자와 0 이상 정수 |

명시된 필드는 모두 필수이며 다른 필드는 허용하지 않는다. `artworks/{artworkId}/chunks/{chunkId}`는 `index`(0 이상 정수), `pointsJson`(1~200,000자 문자열)을 가진다. JSON 형식은 `[ {"latitude": 37.0, "longitude": 127.0, "recordedAtMillis": 1700000000000} ]`다. 청크는 `index` 순서로 읽는다. 각 좌표의 유효성, 순서와 청크 개수는 규칙에서 검증하지 않으므로 클라이언트가 확인한다. 글자 수 제한과 Firestore 문서 바이트 제한은 다르므로 충분히 작은 청크를 사용한다.

## 등록과 조회

1. 사용자에게 경로·닉네임·작품 이름이 다른 사용자에게 공개됨을 안내하고 동의를 받는다. 출발점과 도착점도 경로에 포함된다.
2. 작품 문서를 `DRAFT`로 만든다. 작성자만 초안을 조회하고 경로 청크를 변경할 수 있다.
3. 모든 청크 저장을 완료하고 개수와 순서를 확인한 뒤 `PUBLISHED`로 바꾼다. 업로드 실패 시 동일 작품 ID로 재시도한다. 서버 규칙은 실제 청크의 완성 여부를 보장하지 않는다.
4. 목록은 `artworks`에서 `visibility == PUBLISHED` 조건으로 조회한다. 인증된 사용자는 공개 작품과 그 경로를 읽는다. Firestore 보안 규칙은 필터가 아니므로 조건 없이 전체 작품을 조회할 수 없다.
5. 공개된 동안 경로 청크는 수정할 수 없다. 작성자가 `DRAFT`로 바꿔 비공개로 전환하면 청크를 수정하고 다시 공개할 수 있다. 제목과 닉네임은 작성자가 수정할 수 있으며 닉네임 변경 시 클라이언트가 기존 작품의 닉네임을 갱신해야 한다. 작성자가 비공개로 바꾸면 다른 사용자의 작품 및 투표 조회가 제한된다.

## 투표

`artworks/{artworkId}/votes/{uid}` 문서 하나가 한 표다. UID는 현재 Firebase 인증 UID여야 한다. 필드는 `createdAt` timestamp 하나뿐이다.

- 공개 작품에 `create`하면 한 표가 생긴다. 같은 UID의 문서가 이미 있으면 새 문서를 또 만들 수 없고 업데이트도 거부된다. 재시도 전 본인 투표 존재 여부를 확인한다.
- 자신의 투표 문서를 `delete`하면 취소된다. 다른 사람의 투표는 수정하거나 삭제할 수 없다. 자기 작품 투표는 현재 허용한다.
- 인증된 사용자는 공개 작품의 투표 목록을 읽을 수 있다. 표 수는 해당 하위 컬렉션의 `count()` 집계로 구한다. 작품별 집계 읽기에 따른 비용과 지연을 고려한다. 현재는 표 수로 작품을 서버에서 정렬하는 인기순 기능을 제공하지 않는다.
- 익명 계정은 재설치 등으로 새 UID를 받을 수 있으므로 엄격한 인당 중복 방지는 보장하지 않는다. 점수나 투표의 진위는 서버에서 검증하지 않는다.

## 현재 제한

작품 문서와 하위 청크·투표의 영구 삭제는 아직 제공하지 않는다. 비공개 전환은 조회를 제한하지만 서버 데이터 자체를 삭제하지 않는다. 삭제·탈퇴, 공개 범위와 땅따먹기는 별도 설계가 필요하다. 규칙 변경을 실제 Firebase에 적용하려면 올바른 프로젝트에서 `firebase deploy --only firestore:rules,firestore:indexes,auth --project <프로젝트 ID>`를 실행한다. `firebase.json`의 인증 공급자 목록은 기존 Google 설정과 익명 인증을 함께 유지한다.

목록 페이지, 내 순위와 닉네임 변경 절차는 [클라이언트 조회·프로필 계약](firebase-client-queries.md)을 따른다.
